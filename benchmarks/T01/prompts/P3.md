Implement the following T01 quest browser contract:

1. GET /api/quests returns HTTP 200 with {"quests": [...]} using all fixture quests, ordered by case-insensitive title then ID ascending. Never mutate the fixture.
2. Optional q is a case-insensitive literal substring of title; trim its surrounding whitespace. Empty q matches all. Optional difficulty is exactly easy, medium or hard. Optional status is exactly open or closed. Combine supplied filters using AND. An explicitly empty difficulty/status, an invalid enum, or a repeated supported query key returns 400 INVALID_REQUEST. Ignore unknown query keys. No pagination.
3. GET /api/quests/{quest_id} returns the complete fixture object with HTTP 200, or 404 NOT_FOUND for an unknown ID. Errors use the common error envelope with a nonempty message.
4. UI loads all quests initially; provide labeled search, difficulty and status controls with an explicit keyboard-operable Apply button. A quest has a button named View <title>. Opening details preserves filter values and the current list. Display all fixture fields except ID, including the description. No route/navigation library is required.
5. During requests show a role=status loading message; a successful empty list shows a role=status empty message; request failure shows a nonempty role=alert. A later request's result must not be overwritten by an earlier response. Detail failures must not discard the current list. All controls work using keyboard input and native focus behavior.
6. Preserve /health on both services. Do not add quest writes, acceptance, reservations, database access, authentication, pagination or new dependencies.

Examples: difficulty=easy yields q-ash then q-delta; status=open&difficulty=easy yields q-ash; q=%20BEACON%20 yields q-beacon; difficulty=legendary returns 400. A text search with no matches returns 200 and an empty array.
